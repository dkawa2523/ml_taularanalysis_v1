# 次フェーズ（T041〜T050）の狙い

このフェーズは「機能追加」よりも、**ClearML 運用が破綻しないこと**と **業務投入での再現性/監査性**を最優先にしています。

- T041: ClearML UI契約の lint（doctor/CI）で逸脱を早期検知
- T042: Template Task を標準化し、Clone運用を安定化
- T043: exec_policy（queue/budget/上限）でタスク爆発を防止
- T044: registry metadata / recommendation tagging の運用フロー完成
- T045: 結論を1ページ（report.md + optional ClearML Report）
- T046: alerting（file sink + optional webhook、UI上の状態表現）
- T047: env snapshot と lockfile 導線で再現性強化
- T048: data quality gate を強化（リーク疑い/ID列/高カーディナリティ）
- T049: 監視→再学習→比較→推薦→推論時選択 の retrain 導線
- T050: serving hardening（認証/ステージ選択/監査ログ/入力検証）

運用上の原則：
- 新機能は YAML で opt-in（デフォルトOFF）
- ClearML Properties は検索用の最小セットに限定し、詳細は Artifact（json/md）へ寄せる
- ml-platform の変更は前提にしない（platform_adapter 経由）
